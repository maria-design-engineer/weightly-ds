# Weightly DS — дизайн-система продукта в коде

Библиотека компонентов и витрина Storybook для приложения Weightly — мобильного веб-приложения для тяжелоатлетов. Продукт подключает её пакетом; своих экранов здесь нет.

Собрана по UI-kit в Figma и его описанию в `docs/ui-docs/design-system/` — они живут в репозитории документов, отдельно от кода. Эталон — файл Figma: разошлись описание и файл, верен файл.

## Карта документа

```
├─ Требования — что стоит на машине
├─ Установка с нуля — шаги до открытой витрины
├─ Команды — что чем запускается
├─ Что отдаёт сборка — состав пакета
├─ Как устроен проект — где что лежит
├─ Витрина по публичному адресу — как публикуется
└─ Чего здесь нет — база, секреты, экраны продукта
```

## Требования

```
├─ Node 24.16.0 — на нём собрано и проверено; та же версия закреплена в автосборке
├─ npm 11.13.0 — приезжает вместе с Node
└─ интернет при первой сборке — гарнитура Golos Text грузится с Google Fonts
```

База данных, переменные окружения и внешние сервисы библиотеке не нужны.

## Установка с нуля

**1. Поставить зависимости по файлу замка.**

```
npm ci
```

`npm ci` вместо `npm install` не случайно: он ставит ровно то, что записано в `package-lock.json`. Автосборка делает так же, поэтому витрина на публичном адресе совпадает с локальной.

**2. Проверить, что собирается.**

```
npm run build
```

Верный ответ — три файла в `dist/` и ни одного `index.html`: библиотека собирается в пакет, а не в сайт. На 03.09.2026 вывод такой:

```
dist/ds.css  59.94 kB │ gzip: 8.79 kB
dist/ds.cjs  21.93 kB │ gzip: 6.47 kB
```

**3. Открыть витрину.**

```
npm run storybook
```

Откроется `http://localhost:6006` — каталог компонентов. Каждый компонент открывается сам по себе, каждое состояние показано отдельной карточкой с подписью.

## Команды

```
├─ npm run build           — собрать пакет и типы в dist/
├─ npm run lint            — проверить код, oxlint
├─ npm run storybook       — витрина на localhost:6006
└─ npm run build-storybook — собрать витрину в storybook-static/
```

Команд, стирающих данные, в проекте нет: данных нет тоже.

Строгая проверка типов включена — `strict` в `tsconfig.app.json` и `tsconfig.node.json`. Собирается `npm run build`, она же зовёт `tsc`.

## Что отдаёт сборка

```
├─ dist/ds.js          — сборка для сборщиков
├─ dist/ds.cjs         — сборка для тех, кто требует пакет по-старому
├─ dist/ds.css         — токены, стили и вид компонентов, подключается отдельно
└─ dist/types/         — описания типов
```

React и React DOM помечены внешними: они приходят из приложения. То же у Base UI и иконотеки — иначе одна библиотека приедет дважды, и состояние в двух копиях разойдётся.

Продукт подключает библиотеку так:

```
import { Button } from 'ds'
import 'ds/styles.css'
```

## Как устроен проект

```
├─ src/components/     — 36 компонентов, каждый своей папкой
│   ├─ <Имя>.tsx       — компонент: наши свойства снаружи, чужая библиотека внутри
│   ├─ <Имя>.css       — вид, только на токенах
│   ├─ <Имя>.stories.tsx — story на каждое значение оси плюс Playground
│   └─ constants.ts    — значения осей из UI-kit; лежит у 22 из 36, у остальных осей нет
├─ src/tokens/         — токены и стили кита, четыре режима: Light, Dark, Light HC, Dark HC
├─ src/Overview.stories.tsx      — обзорная страница, по ней дизайн принимает витрину
├─ src/ScreenExamples.stories.tsx — экраны продукта, собранные из библиотеки
└─ src/index.ts        — точка входа: чего в ней нет, того для приложения не существует
```

Один из тридцати шести — `Icon` — ни стилей, ни своей story не имеет: это обёртка над иконотекой, и показывать в каталоге у неё нечего.

Стек: Vite 8.2.2 в режиме библиотеки · React 19.2.8 · TypeScript 6.0.3 · Storybook 10.6.0 · Base UI 1.7.0 — из неё приходит поведение, вид написан свой · `@gravity-ui/icons` 2.22.0 · oxlint 1.81.0.

Версии в `package.json` записаны точными числами, без `^` и `~`: диапазон однажды приведёт другую версию и разойдётся молча.

## Витрина по публичному адресу

Витрина живёт по адресу [maria-design-engineer.github.io/weightly-ds](https://maria-design-engineer.github.io/weightly-ds/).

Публиковать руками нечего: отправка в `main` сама пересобирает витрину и выкладывает её. Настройка — `.github/workflows/pages.yml`, версии шагов там точные по той же причине, что и в `package.json`.

Зелёный прогон автосборки не доказывает, что доехало: откройте адрес и убедитесь, что на нём последняя правка. Старая версия у другого человека — обычно кэш браузера, а не сборка.

## Чего здесь нет

```
├─ базы, миграций, начальных данных — библиотека ничего не хранит
├─ файла .env и секретов — наружу она не ходит
├─ экранов продукта — они собираются в отдельном репозитории на этой библиотеке
└─ описания дизайн-системы — оно в репозитории документов, docs/ui-docs/design-system/
```

Примеры в витрине выдуманы намеренно: она выложена по публичному адресу целиком, и настоящим именам, адресам и числам там не место.
